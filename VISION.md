# Vision

> *Every successful project begins by asking what it wants to build.*
> *The best projects also ask what they want to change.*
> NetCanvas exists to change the way people think about designing, configuring, and managing computer networks.

---

## The Long-Term Goal

NetCanvas is not simply another network management application.

It is an attempt to replace the traditional, device-centric approach to networking with one centered around intent.

Users should design the network they want.

The software should implement it.

The long-term objective is simple:

> People should design networks - not configure hardware.

---

## The Canvas Is the Interface

Most networking software treats diagrams as documentation.

NetCanvas treats the canvas as the configuration interface.

The network exists first as a visual model.

Configuration, documentation, deployment plans, and vendor-specific implementations are all derived from that model.

The canvas is not a picture of the network.

The canvas *is* the network.

---

## Networks Should Outlive Hardware

Networking vendors will continue to evolve.

Products will be discontinued.

Controllers will change.

Platforms will come and go.

A well-designed network, however, should remain valuable regardless of the hardware used to implement it.

NetCanvas aims to separate network design from vendor implementation so that replacing hardware does not require redesigning the network itself.

A network configuration should be portable.

Only its implementation should change.

---

## Networking Should Be Understandable

Professional networking has accumulated decades of terminology, conventions, and vendor-specific concepts.

Much of that complexity is necessary - but the incomprehensibility should not be.

NetCanvas does not attempt to eliminate complexity.

It attempts to organize it and make it unnecessary.

Simple tasks should remain simple.

Advanced capabilities should remain available.

Users should spend their time making design decisions rather than hunting through nested menus and dialogs for some deeply buried configuration item.

---

## Simplified Networking Should Not Penalize Experts

Experts should not have to fight the interface. They should not be forced through unnecessary wizards or have advanced features and configuration options hidden from them.

NetCanvas should accelerate experienced users while remaining welcoming to beginners.

Power and simplicity are not opposing goals.

They are design goals that must coexist.

---

## Security Should Be Natural

Security should not depend on remembering dozens of best practices after the network has already been built.

Instead, NetCanvas should encourage secure designs from the beginning:

- Network segmentation.
- Least privilege.
- Protected management networks.
- Meaningful warnings.
- Safe defaults.

The software should help users build secure networks without requiring them to become security experts.

---

## Documentation Should Never Become Outdated

Documentation is often treated as a separate task.

It is written after deployment, gradually falling behind reality until no one trusts it.

NetCanvas aims to eliminate this problem by treating documentation as another _view_ of the canonical network model.

The documentation changes because the network changes - not because someone remembered to update a document.

---

## Vendor Support Should Grow Naturally

NetCanvas will not be defined by the platforms it supports today.

The architecture should make supporting new platforms an incremental improvement rather than a fundamental redesign.

Whether the network is deployed to Omada, UniFi, MikroTik, pfSense, or platforms that do not yet exist, the user's mental (and visual) model should remain consistent.

The hardware is an implementation detail.

The network is the product.

---

## Automation Should Build Confidence

Automation is often associated with removing human involvement.

NetCanvas has a different goal.

Automation should make users more confident in the changes they are making:

- Every deployment should be understandable.
- Every proposed change should be reviewable.
- Every action should be explainable.
- Users should always know what will happen before it happens.

---

## Artificial Intelligence Should Assist, Not Replace

Artificial intelligence has enormous potential to make networking more approachable.

It should explain unfamiliar concepts, recommend better designs, identify potential problems, answer questions in context, suggest improvements.

It should never become a substitute for understanding.

Users remain responsible for their networks.

AI should make better decisions easier — not make decisions for them.

---

## An Open Platform

No individual or small team can anticipate every networking platform, deployment model, or workflow.

NetCanvas should therefore be designed to grow:

- New platform drivers.
- New deployment targets.
- New validation engines.
- New visualization tools.
- New integrations.

The platform should become more capable without forcing users to relearn how it works.

---

## Success

Success will not be measured by:

- The number of supported vendors.
- The number of managed devices.
- The size of the deployment.
- The amount of automation.

Success will be measured by something much simpler.

A person sits down to build a network.

They never wonder where a particular vendor hid a configuration option.

They never search through nested menus trying to remember what something is called.

They simply draw the network they want.

NetCanvas takes care of the rest.

---

## Closing Thoughts

The networking industry has spent decades teaching people to think like their hardware.

NetCanvas seeks to reverse that relationship.

The software should understand the hardware.

The user should understand the network.

When that distinction disappears...

...NetCanvas will have achieved its vision.
